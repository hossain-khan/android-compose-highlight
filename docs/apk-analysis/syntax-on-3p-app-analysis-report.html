APK Syntax Highlighting Analysis

ChatGPT vs Claude Android Apps — April 21, 2026

← Home

Summary: ChatGPT uses a fully native Android rendering pipeline — CommonMark parsing fed through a custom Jetpack Compose rich-text library with Android Span-based coloring. Claude takes a hybrid approach, bundling Highlight.js v11.10.0 locally and running it through a custom token bridge that feeds native ForegroundColorSpan for inline chat, while using a WebView with full Highlight.js rendering for expanded code views.

ChatGPT Fully Native

Approach

ChatGPT renders syntax-highlighted code entirely through native Android APIs. Markdown is parsed into an AST by CommonMark, then rendered via OpenAI's custom fork of the compose-richtext library into Jetpack Compose components. Syntax coloring is applied using Android's SpannableStringBuilder with ForegroundColorSpan, StyleSpan, and TypefaceSpan.

Claude Highlight.js Hybrid

Approach

Claude bundles Highlight.js v11.10.0 locally in the APK assets, along with a custom token-highlight.js wrapper that extracts token positions and types as JSON triplets ([start, end, typeId]). The app uses two rendering paths: inline chat code blocks are colored via native ForegroundColorSpan on SpannableString, while full-screen code views use a WebView with Highlight.js and Atom One Dark/Light CSS themes from CDN.

Security Measures

  • Base64 encoding: Source code is Base64-encoded before passing to JavaScript, preventing injection
  • URL whitelisting: WebViewClient restricts resource loading to cdnjs.cloudflare.com only
  • WebView isolation: Custom shouldInterceptRequest() blocks all other external requests

Conclusions

ChatGPT went fully native: a CommonMark-based parsing pipeline that converts markdown ASTs into Android Spans rendered through Jetpack Compose. This avoids WebView overhead entirely and keeps the code rendering path consistent with the rest of the UI. The tradeoff is complexity — OpenAI maintains a custom fork of compose-richtext and implements their own token-to-color mapping.

Claude leveraged the well-established Highlight.js ecosystem, gaining 190+ language grammars and battle-tested tokenization for free. The clever token-highlight.js bridge extracts structured token data that gets mapped to native Android Spans for inline rendering, avoiding the performance penalty of a WebView in the chat scroll. The WebView path is reserved for full-screen views where richer HTML rendering is appropriate. The tradeoff is a CDN dependency for theme CSS in the full-screen path and the overhead of bridging between JavaScript and native code.

Both approaches are well-engineered solutions to the same problem, optimized for their respective priorities: ChatGPT for UI consistency and native performance, Claude for leveraging proven open-source tooling with minimal custom code.

Analysis performed on APKs extracted via ADB from a physical device. Decoded using apktool 3.0.2. All findings based on static analysis of smali bytecode, bundled assets, and resource files.
