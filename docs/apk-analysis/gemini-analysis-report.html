Summary: Gemini takes the most extreme approach of all four analyzed apps — it is a ~5 MB thin shell/trampoline that contains zero local UI rendering logic for conversations, code, or syntax highlighting. The APK's sole purpose is to launch the real Gemini experience hosted inside the Google App (AGSA / com.google.android.googlequicksearchbox). The BardEntryPointActivity creates an intent to AGSA, calls startActivity(), then immediately finish()es itself. There are no bundled JS, CSS, HTML, syntax highlighting libraries, code-related color resources, or monospace fonts. All rendering — including any syntax highlighting of code blocks — happens inside AGSA or is driven entirely by the server.

GitHub's is 42 MB with Primer CSS themes and jsoup HTML parsing. Gemini's 4.8 MB APK is an order of magnitude smaller because it ships almost no application logic.

Approach: Trampoline to Google App (AGSA)

The Gemini APK is not a standalone app — it is a trampoline. When the user taps the Gemini icon, BardEntryPointActivity runs through a series of checks (is AGSA installed? Is the version high enough?) and then launches an intent into the Google App:

// Reconstructed from BardEntryPointActivity.smali onCreate()
Intent intent = new Intent("android.intent.action.VIEW");
intent.setData(Uri.parse("https://bard.google.com/android?source=bardshell"));
intent.setPackage("com.google.android.googlequicksearchbox");
intent.putExtra("shell_app_version", versionCode.toString());
intent.putExtra("shell_app_on_create", elapsedRealtime);
startActivity(intent);
finish();  // Shell immediately exits

The manifest confirms this architecture: BardEntryPointActivity uses android:relinquishTaskIdentity="true" (hands the task stack to the launched activity) and android:theme="@android:style/Theme.Translucent" (invisible to the user during the trampoline).

AGSA Version Gating

The smali reveals a sophisticated version-checking system before the trampoline fires. The shell app checks if AGSA is installed and whether its version meets minimum thresholds:

  • Pixel 9 path — isAgsaAboveMinVersionForPixel9: checks AGSA version against a Pixel 9-specific minimum
  • Android 9+ path — isAgsaAboveMinVersionForAndroid9Devices: checks against a general minimum
  • General shell path — isAgsaAboveMinVersionSupportingShellApp: fallback version check

If AGSA is missing or too old, the shell reports AGSA_DISABLED, UPDATE_AGSA, or FAILURE_AGSA_VERSION_TOO_LOW and shows an error or redirect instead of launching the experience.

Widget

The only non-trampoline UI component is a home screen widget (RobinToolBarAppWidgetReceiver) that uses Glance (Jetpack's widget framework). This widget provides quick access buttons but does not render conversation content or code.

Implications for Syntax Highlighting

Since the Gemini shell APK contains zero rendering logic, syntax highlighting for code blocks must happen in one of two places:

  1. Inside AGSA — The Google App likely contains a WebView or native rendering path for Gemini conversations, including code blocks. This could use server-side highlighting (similar to GitHub) or a client-side library bundled within AGSA's much larger APK.
  2. Server-side — Google's backend could return pre-highlighted HTML/markdown that AGSA simply renders, similar to how GitHub's API returns .pl-* tagged HTML.

Without decompiling the Google App itself (which is significantly larger and more complex), we cannot determine the exact mechanism. However, the Gemini shell APK definitively does not participate in syntax highlighting in any way.

Conclusions

Gemini represents the most radical architecture among the four apps: it doesn't even attempt to render its own UI. The ~5 MB APK is a pure launcher shell that trampolines into the Google App, where the actual Gemini experience lives. This is a deliberate Google strategy — by embedding Gemini inside AGSA, Google can update the conversational AI experience through Google App updates without requiring a separate Gemini app update, and can share infrastructure (authentication, settings, search integration) with the broader Google ecosystem.

The tradeoff is a hard dependency on the Google App — without AGSA installed at a sufficient version, the Gemini shell shows an error. The version-gating logic (with separate thresholds for Pixel 9, Android 9+ devices, and a general minimum) reveals that AGSA's Gemini support has evolved through multiple releases with device-specific rollouts.

For the specific question of syntax highlighting: the Gemini shell APK provides no evidence whatsoever about how code is highlighted. That logic lives entirely within AGSA or is server-driven. Analyzing AGSA itself would require a separate investigation of a much larger and more complex APK.

Analysis performed on APK extracted via ADB from an emulator. Decoded using apktool 3.0.2. All findings based on static analysis of smali bytecode, bundled assets, and resource files.
