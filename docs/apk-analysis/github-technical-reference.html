Claim: The app contains no client-side syntax parsing library (highlight.js, Prism, CodeMirror, TreeSitter, Shiki, Markwon syntax plugin). Highlighting is done server-side.

10 declared dependencies. None are syntax highlighting libraries. No highlight.js, Prism, Shiki, CodeMirror, TreeSitter, Markwon, or CommonMark. The only text-processing library is jsoup (HTML parser) — used to convert server-generated HTML into native Spans, not to parse or highlight code.

5. JavaScript Bridge — markdown.js

Claim: The JS bridge provides content injection and native communication but contains no syntax parsing logic.
github-decoded/assets/webview/markdown.js — key methods (385 lines total) js 
class GitHub {
  // Send message to native Android app
  _sendMessage (name, message) {
    const payload = message
    payload.messageName = name
    payload.id = this._id
    window.native.sendMessage(JSON.stringify(payload))
  }

  // Monitor content height for native layout
  _addHeightListener () {
    if (typeof ResizeObserver !== 'undefined') {
      const resizeObserver = new ResizeObserver(entries => {
        this._updateHeight()
      })
      resizeObserver.observe(document.body)
    }
    // ... fallback listeners for details, video, img
  }

  // Main entry: inject pre-highlighted HTML into DOM
  load (id, html, isCommitSuggestedChangesEnabled,
        isTaskListCompletionEnabled, overridePos, overrideVal) {
    this._id = id
    const content = document.getElementById('content')
    content.innerHTML = html     // HTML already has <span class="pl-*"> tokens
    // ... handle suggested changes buttons, task list checkboxes
    this._didLoad()
    this._updateHeight()
  }
}

window.github = new GitHub()
The load() method takes raw HTML and sets it as innerHTML. The HTML already contains <span class="pl-*"> syntax tokens from the server. The JS does zero parsing — it only handles UI interactions (height reporting, suggested changes, task lists, anchor scrolling). Compare this to Claude's token-highlight.js which actively runs highlight.js to tokenize code.

11. jsoup HTML Parsing for Native Spans

Claim: jsoup parses server HTML containing pl-* classes and feeds the results to the native span conversion pipeline.
github-decoded/smali_classes4/uz0/d.smali — jsoup integration smali 
# Parse HTML string using jsoup (obfuscated as kc1 package)
invoke-static {p0}, Lcom/google/android/gms/.../c5;->k0(Ljava/lang/String;)Lkc1/g;

# Configure parser settings

# Parse document and extract body
iput-object v3, p2, Lkc1/g;->C:Lkc1/f;
invoke-virtual {p2}, Lkc1/g;->O()Lkc1/j;   # get document body

# Process spans from parsed HTML
invoke-static {v2, p0}, Ly9/a;->V(Lmc1/r;Lkc1/o;)V  # convert to spans

jsoup (package kc1) parses the server HTML. The parsed DOM is then walked to extract pl-* classes, which are mapped through uz0/b.smali to colors, and applied as sd/f StyleSpan instances on a SpannableString.
