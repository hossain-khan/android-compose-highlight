Le Chat by Mistral AI

Syntax Highlighting & Code Rendering Implementation Analysis

Executive Summary

Le Chat (v1.21.2) is a React Native (Expo SDK 55) AI chat application by Mistral AI that uses Highlight.js for syntax highlighting tokenization. The app runs on a Hermes JS engine with a ~15.6 MB bytecode bundle. Unlike WebView-based editors, Le Chat performs highlighting entirely within the JavaScript/React Native layer: Highlight.js tokenizes code blocks from AI responses, and the tokens are rendered using React Native Text components with styled spans, enhanced by NativeWind (Tailwind CSS for RN). The app also bundles React Native Skia which may be used for custom drawing of code blocks or other rich content. This is a "tokenize in JS, render natively" pattern — similar to how Claude and Perplexity handle code highlighting, but executed entirely within the React Native runtime rather than bridging to platform-native views.

Syntax Highlighting Implementation

Approach: Highlight.js Tokenization + React Native Text Rendering

Highlight.js React Native Native Text Spans

Le Chat uses Highlight.js as its syntax highlighting engine, confirmed by the presence of hljs- prefixed CSS token classes and internal Highlight.js constants (beginKeywords, COMMENT, C_LINE_COMMENT_MODE) found in the Hermes bytecode bundle.

The rendering surface is React Native Text components (not WebView). Code tokens produced by Highlight.js are mapped to styled Text spans using NativeWind/Tailwind utility classes. This approach keeps highlighting performant and integrated with the native scroll/layout system while leveraging Highlight.js's extensive language grammar coverage.

Evidence

  • 30+ hljs CSS classes found in Hermes bytecode — hljs-keyword, hljs-string, hljs-comment, hljs-number, hljs-title, hljs-type, hljs-variable, hljs-built_in, hljs-literal, etc.
  • Highlight.js internal constants — beginKeywords, COMMENT, C_LINE_COMMENT_MODE patterns
  • Large language grammar sets — vim commands, Maya/MEL, regex patterns indicate many languages bundled
  • No WebView rendering for code — WebView (RNCWebView) is present but used for auth flows (hCaptcha, OAuth)
  • NativeWind (Tailwind CSS for RN) — extensive Tailwind utility classes for styling tokens

Rendering Surface Analysis

React Native Text (Primary) + Possible Skia Canvas

Code highlighting in Le Chat is rendered using React Native's native Text components with styled spans. The evidence supports this conclusion:

  • NativeWind/Tailwind styling — Token colors are applied via utility classes mapped to RN styles
  • No WebView for code — RNCWebView exists but the WebView bridge patterns (window.ReactNativeWebView?.postMessage) reference auth/challenge flows, not code rendering
  • React Native Skia available — com/shopify/reactnative/skia/RNSkiaPackage is registered; may be used for custom code block chrome, backgrounds, or canvas-based features
  • No native Android highlighting — No ForegroundColorSpan, SpannableString, or Compose text styling in native classes

This is the same pattern used by Claude and Perplexity: tokenize with a JS library (hljs), then render tokens as colored text spans in the native UI framework. Le Chat differs in that it does this entirely within the React Native JS layer, without needing a native Android bridge for the rendering step.

Key Insights

  1. Highlight.js remains popular in RN AI apps. Even in 2026, Highlight.js is the go-to choice for React Native chat apps that need code highlighting. Its large grammar library and simple API make it ideal for rendering AI-generated code blocks with unknown languages.
  2. The "tokenize in JS, render natively" pattern is standard. Le Chat, Claude, and Perplexity all use the same fundamental approach: parse code with a JS library (hljs or similar), then render tokens as colored text spans. The differences are in where the rendering happens (RN Text vs. native Android views).
  3. WebView is avoided for code rendering. Despite having RNCWebView available, Le Chat uses it only for auth flows. Native text rendering provides better scroll performance, accessibility, and text selection for code blocks in a chat interface.
  4. React Native Skia adds a Compose-like canvas. The inclusion of Skia suggests Le Chat may draw custom UI elements (code block decorations, backgrounds, copy buttons) using GPU-accelerated canvas operations rather than standard RN views.
  5. Large hljs grammar set impacts bundle size. The 15.6 MB Hermes bundle (vs. Replit's 7.5 MB) partly reflects bundling many Highlight.js language grammars. A native library can offer more selective grammar loading.
  6. "Vibe Code" represents a new category. Le Chat's dedicated coding workflow goes beyond simple code display — it is an agent-driven code generation experience that requires robust highlighting for the output.
  7. Unconventional font choice signals brand differentiation. VCROSDMono (retro pixel monospace) is a deliberate stylistic choice that makes Le Chat's code blocks visually distinct from competitors using standard developer fonts.

Conclusions

Le Chat demonstrates the prevailing pattern for AI chat apps on mobile: use a well-established JavaScript syntax highlighting library (Highlight.js) for tokenization, then render the tokens using the app's native UI components. This trades some performance (JS thread parsing overhead) for maximum language coverage and cross-platform code reuse.

For a native Compose highlighting library, Le Chat's approach validates the market need: a purpose-built native solution could offer the same breadth of language support with better performance characteristics (no JS bridge, direct AnnotatedString rendering, lazy tokenization), while being usable by both native Android apps and Kotlin Multiplatform projects that want to avoid the React Native / JS runtime dependency entirely.

The 30+ hljs token classes found provide a useful reference for ensuring comprehensive token type coverage in any highlighting library implementation.
